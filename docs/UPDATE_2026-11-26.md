# Update 26.11.2026 – Vertrags-Upload und Freigabe der Registrierungen

## Ursache

Manche Browser bzw. Firmen-PCs melden PDFs ohne oder mit falschem Dateityp (leer, `application/octet-stream`, `application/x-pdf`).
Der Worker hat solche Dateien mit „Dateityp nicht erlaubt“ (HTTP 415) abgelehnt. Ohne hochgeladenen Vertrag war auch die Freigabe der Registrierung gesperrt.

## Änderungen

| Datei | Änderung |
|---|---|
| `src/worker.js` | Dateityp wird beim Upload robust erkannt: gemeldeter Typ → Dateiendung → Dateianfang (echte PDFs werden immer erkannt). Andere Dateien (z. B. `.exe`) bleiben gesperrt |
| `src/worker.js` (eingebettete `shim.js`) | Übergibt den von der App ermittelten Dateityp und liefert verständliche Fehlercodes |
| `app/index.html` | Alle Uploads mit Typ-Erkennung, iPhone-Fotos (HEIC) werden zu JPG; klare Fehlermeldungen |
| `app/index.html` | Verwaltung → Freigaben: neuer Button „Unterschriebenen Vertrag hochladen“, wenn der Vertrag per E-Mail/Post kam – danach ist die Freigabe möglich |
| Aufgeräumt | `index.html` im Hauptordner und `app/index (7).html` entfernt – gültig ist nur `app/index.html` |

Unverändert: `wrangler.toml` (IDs), Daten in D1/KV, Ablauf mit zwei Freigaben (Vertrieb + Buchhaltung).

## Einspielen

| Schritt | Was tun |
|---|---|
| 1 | `src/worker.js`, `app/index.html` und `docs/UPDATE_2026-11-26.md` auf GitHub ersetzen bzw. hinzufügen (Commit auf `main`) – Cloudflare deployt den Worker automatisch |
| 2 | Auf GitHub `index.html` (Hauptordner) und `app/index (7).html` löschen |
| 3 | `…/konten` → „1 · App-Datei hochladen“ → `app/index.html` |
| 4 | Seite neu laden, unter `#verwaltung` → Freigaben testen |

Daten bitte **nicht** neu importieren.
